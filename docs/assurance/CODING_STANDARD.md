# Rust 与 Slint 编码标准

本标准自 v2.1.0 起适用于新代码；修改旧代码时必须在合理范围内同步收敛。

## 1. 通用规则

- 每个安全、状态、资源或时序行为必须追踪到 `SWR-*` 需求；
- 使用封闭枚举和类型表达状态，禁止用任意字符串表示控制状态；
- 所有外部输入在资源获取前验证长度、范围、格式和组合约束；
- 资源必须有上限，并定义满载、超时、取消和清理行为；
- 错误消息不得包含 API Key、密码、代理凭据、PCM、字幕正文或原始服务端载荷；
- 使用单调时钟测量持续时间；墙上时钟只用于展示和审计时间戳；
- 公共行为变化必须同时修改需求、追踪和测试。

## 2. Rust 规则

- 新的纯 Rust 核心 crate 使用 `#![forbid(unsafe_code)]`；Slint 生成代码需要其宏内部的受限 `unsafe` 许可，因此桌面入口使用 `#![deny(unsafe_code)]` 约束手写代码并把生成模块视为单独依赖边界；必须使用 `unsafe` 的平台 FFI 应隔离到专用 crate，记录不变量并单独评审；
- 生产路径禁止 `unwrap()`、`expect()`、未检查数组索引和可触发 panic 的输入假设；
- `Mutex` 中毒必须采用明确恢复或故障策略，不能静默忽略状态损坏；
- 状态迁移使用总是可审查的状态机；无效迁移返回错误且不得部分修改状态；
- 整数转换、计数和容量运算使用受检或饱和操作；
- 敏感值所有权尽量短，释放前清零；禁止在 `Debug`、日志或 URL 中暴露；
- 实时回调额外遵守路线图中的零分配、无锁、无 I/O 规则；
- `cargo fmt --check`、`cargo clippy --all-targets --all-features -- -D warnings` 和锁定测试属于合并门。

## 3. Slint/UI 规则

- UI 不直接持有 PCM，不直接操作网络协议；
- UI 只能发出有界命令并接收脱敏状态快照；
- 控件索引必须有显式安全默认值，不能依赖数组索引 panic；
- 不可用能力必须禁用或明确提示，禁止用假“运行中”状态代替未接入后端；
- 翻译与转写模式约束必须由核心再次执行，不能只依赖控件状态。

## 4. 测试规则

- 测试名包含被验证的需求 ID，例如 `swr_core_001_*`；
- 每项低层需求至少有一个自动化验证或明确的分析/真机验证记录；
- 测试包含正常、边界、非法输入、重复事件、乱序事件和故障路径；
- 测试不得依赖公网、真实密钥或不受控时间等待；
- 修复缺陷前先增加能够稳定复现缺陷的测试。
