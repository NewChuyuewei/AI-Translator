# 软件需求基线

## translator-core v2.1.0 增量

| ID | 需求 | 验证 |
|---|---|---|
| SWR-CORE-001 | 会话生命周期必须使用封闭状态集合，并只允许 Idle/Error→Connecting→Running→Stopping→Idle 的已定义正常迁移；连接或运行故障进入 Error。 | 单元测试、代码评审 |
| SWR-CORE-002 | 无效、重复或乱序生命周期事件必须被拒绝，且不得产生部分状态更新。 | 鲁棒性单元测试 |
| SWR-CORE-003 | 会话选项必须在网络、音频或文件资源获取前验证密钥长度、语言、模型组合、代理、设备名和字幕缩放范围。 | 边界/无效输入测试 |
| SWR-CORE-004 | 验证和代理错误不得回显密钥、用户名或密码。 | 脱敏测试、代码评审 |
| SWR-CORE-005 | 提取后的核心序列化格式必须保持既有设置和前端 IPC 的字段名及枚举值兼容。 | 序列化回归测试 |
| SWR-UI-001 | 后端适配器未接入时，Slint 壳层不得进入运行状态、采集音频或声称已连接。 | 代码评审；后续 UI 集成测试 |
| SWR-CFG-001 | npm、Cargo workspace、Slint、Tauri 过渡入口、Android 和发行包装版本必须一致，且只能通过受控脚本修改。 | `npm run test:version` |

## 需求约束

- 这里记录的是当前增量需求，不替代完整产品需求；后续迁移必须逐批补全协议、配置、保险库、诊断、音频和窗口需求。
- “必须”需求在对应版本验收前不得以 TODO、人工假设或仅编译通过关闭。
