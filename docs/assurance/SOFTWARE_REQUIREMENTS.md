# 软件需求基线

## translator-core v2.1.0 增量

| ID | 需求 | 验证 |
|---|---|---|
| SWR-CORE-001 | 会话生命周期必须使用封闭状态集合，并只允许 Idle/Error→Connecting→Running→Stopping→Idle 的已定义正常迁移；连接或运行故障进入 Error。 | 单元测试、代码评审 |
| SWR-CORE-002 | 无效、重复或乱序生命周期事件必须被拒绝，且不得产生部分状态更新。 | 鲁棒性单元测试 |
| SWR-CORE-003 | 会话选项必须在网络、音频或文件资源获取前验证密钥长度、语言、模型组合、代理、设备名和字幕缩放范围。 | 边界/无效输入测试 |
| SWR-CORE-004 | 验证和代理错误不得回显密钥、用户名或密码。 | 脱敏测试、代码评审 |
| SWR-CORE-005 | 提取后的核心序列化格式必须保持既有设置和前端 IPC 的字段名及枚举值兼容。 | 序列化回归测试 |
| SWR-UI-001 | 后端适配器未接入时，Slint 壳层不得进入运行状态、采集音频或声称已连接。 | 代码评审；后续 UI 集成测试 |
| SWR-CFG-001 | npm、Cargo workspace、Slint、Tauri 过渡入口、Android 和发行包装版本必须一致，且只能通过受控脚本修改。 | `npm run test:version` |
| SWR-PROTO-001 | Gemini setup 构造必须位于不接收 API Key 的纯核心模块，并为四种模型生成明确且模型专属的配置。 | 模型矩阵单元测试、代码评审 |
| SWR-PROTO-002 | 翻译和纯转写 setup 必须保持不同的响应模态和字段语义，禁止转写模式请求或伪造译音。 | 精确 JSON 单元测试 |
| SWR-PROTO-003 | PCM 网络消息必须在 Base64/JSON 分配前执行 1 MiB 输入上限检查，并声明 16 kHz PCM MIME 类型。 | 边界和精确编码测试 |
| SWR-PROTO-004 | 正常停止必须发送仅包含 `audioStreamEnd` 的确定性消息，不得附带残余 PCM。 | 精确 JSON 单元测试 |
| SWR-RX-001 | 服务端文本/二进制数据帧必须在解析前执行 2 MiB 上限与 UTF-8 检查；解析错误不得回显原始载荷。 | 边界、格式和脱敏单元测试 |
| SWR-RX-002 | 服务端解析器必须支持受控的 camelCase/snake_case 字段并输出类型化转写、交互和轮次状态。 | 精确状态单元测试、旧 WebSocket 回归 |
| SWR-RX-003 | 单段转写不得超过 64 KiB，单消息解码音频总量不得超过 1 MiB；Base64 分配前必须先限制编码长度。 | 边界和溢出测试 |
| SWR-RX-004 | 服务端错误与关闭原因必须映射到固定提示，仅允许安全代码/状态进入日志和界面。 | 凭据/正文脱敏测试 |
| SWR-SESSION-001 | 核心必须能在不启动 UI、网络或音频设备的情况下，以内存字节序列执行 setup→响应→停止模拟会话。 | 内存会话单元测试 |
| SWR-SESSION-002 | 只有唯一一次 `setupComplete` 才能启用 PCM；setup 前会话数据、setup 前音频及重复 setup 必须被拒绝。 | 乱序/重复事件测试 |
| SWR-SESSION-003 | 停止必须产生唯一确定的 `audioStreamEnd`，转入 Closed 后拒绝重复停止及后续输入。 | 状态和精确 JSON 测试 |
| SWR-PORT-001 | 核心到 UI 的事件队列必须固定容量；满载时丢弃最旧事件并以饱和计数记录，不得扩容或阻塞生产者。 | 容量、溢出及零容量测试 |
| SWR-PORT-002 | UI 会话端口必须使用类型化命令/事件和核心状态机，并可由无网络内存端口替代以验证生命周期和字幕。 | 内存端口集成测试 |
| SWR-PORT-003 | UI 事件类型不得包含 PCM；字幕和通知文本必须在进入队列前受字符数上限约束。 | 类型评审、Unicode 边界测试 |
| SWR-PORT-004 | 纯转写会话端口必须维持 `transcription_only` 状态且不得启用译音。 | 模型约束和状态测试 |
| SWR-DIAG-001 | 诊断历史必须最多保留 300 条、序号单调递增，满载时保留最新条目；清空返回水位线以拒绝迟到事件。 | 容量、序号和清空测试 |
| SWR-DIAG-002 | 诊断脱敏器必须在信任边界登记 API Key、完整代理 URL、编码/解码后的用户名和密码，并在释放时清零。 | 凭据组合脱敏测试、代码评审 |
| SWR-DIAG-003 | 每条诊断必须移除控制字符并限制为 1,200 字符；短凭据仅按 token 边界替换，避免破坏普通文本。 | Unicode 长度、控制字符和短 token 测试 |
| SWR-DIAG-004 | 诊断级别和字段序列化必须保持现有前端兼容，且核心诊断层不得依赖 Tauri 或 Slint。 | 精确序列化测试、依赖评审 |
| SWR-SET-001 | 普通设置编码不得包含 API Key、代理 URL 或代理凭据；`saveSensitive` 只能表示独立加密保险库的用户选择。 | 明文扫描和序列化测试 |
| SWR-SET-002 | 当前普通设置格式必须在无 UI/文件系统条件下保持既有 camelCase 字段和枚举值的往返兼容。 | 精确往返测试、旧 Tauri 回归 |
| SWR-SET-003 | v1 设置迁移必须清除敏感字段、关闭敏感保存并归一化字幕比例；适配器原子写入成功前不得认为迁移完成。 | 迁移测试、适配器代码评审 |
| SWR-SET-004 | 设置解析必须在 JSON 分配前限制为 1 MiB，并拒绝损坏文件和未知版本，不得崩溃或覆盖原文件。 | 超限、损坏和未知版本测试 |
| SWR-VAULT-001 | 敏感设置必须使用 AES-256-GCM 和独立随机 nonce/salt，并以 PBKDF2-HMAC-SHA256 派生密钥；序列化格式必须兼容现有保险库。 | 加密往返和格式测试 |
| SWR-VAULT-002 | 保险库明文不得出现在序列化文件中，相同输入的重复加密不得产生相同文档，派生密钥和临时明文缓冲必须清零。 | 明文扫描、随机性测试、代码评审 |
| SWR-VAULT-003 | 错误密码、认证标签失败和解密后 JSON 损坏必须返回同一安全错误，不得回显密码、密钥、代理凭据或明文。 | 错误等价和篡改测试 |
| SWR-VAULT-004 | 解密必须在 JSON/Base64 处理前限制输入为 1 MiB，并验证密码长度、版本、算法、迭代次数、salt、nonce 和密文长度。 | 全部边界及损坏格式测试 |
| SWR-NCFG-001 | Slint 原生入口必须使用与旧桌面相同的应用标识配置目录，读取普通设置、执行受控迁移并独立检测保险库，不得回退到当前工作目录。 | 适配器集成测试、路径代码评审 |
| SWR-NCFG-002 | 原生设置和保险库写入必须使用同目录临时文件、文件同步和原子替换；Windows 替换失败必须恢复备份。 | 重复替换测试、平台代码评审 |
| SWR-NCFG-003 | Unix 配置目录和文件权限必须分别限制为 0700 和 0600；所有平台读取必须在分配增长前执行 1 MiB 上限。 | 权限和有界读取测试 |
| SWR-NCFG-004 | Slint UI 必须在操作开始时清空密码属性、操作结束前清零本地密码，并且保险库失败不得启动会话或伪报保存/解锁成功。 | UI 适配器代码评审、后续 Slint 交互测试 |
| SWR-DEV-001 | 音频设备快照必须按麦克风、系统源和播放设备分类，每类最多 128 项；标识、名称和平台文本必须去除控制字符并受字符数限制。 | 容量和文本边界测试 |
| SWR-DEV-002 | 每类设备标识必须唯一，重复项确定性保留首次出现；每类最多一个默认设备，且不得按名称隐式跨类合并。 | 重复标识和默认设备测试 |
| SWR-DEV-003 | 打开设备前必须验证持久化标识仍存在于请求的设备类别；过期或跨类标识必须安全拒绝，空标识明确表示使用后端默认设备。 | 选择有效性测试、旧 Tauri 回归 |
| SWR-DEV-004 | 设备枚举必须通过可替换的类型化 `DeviceProvider`，支持无硬件确定性验证；刷新失败不得覆盖上次有效快照或伪报成功。 | 内存提供器恢复测试、Slint 代码评审 |
| SWR-NDEV-001 | Slint 原生枚举适配器只能查询设备和默认端点，不得在刷新时构建设备流、请求采集权限或启动音频线程；结果必须经过核心有界规范化。 | 依赖/API 代码评审、桌面编译 |
| SWR-NDEV-002 | Slint 必须按核心快照显示麦克风、系统源和播放设备，保留可解析的持久化标识；会话资源获取前必须拒绝已过期或跨类选择。 | 选择映射测试、核心有效性测试、后续真机交互验证 |
| SWR-PXY-001 | 手动及系统解析后的代理端点必须使用封闭的 HTTP CONNECT/SOCKS5 类型，并规范化域名、IPv4、IPv6 和非零端口。 | 协议/地址矩阵测试、旧 Tauri 回归 |
| SWR-PXY-002 | 代理凭据必须执行百分号解码，用户名和密码各限制 255 字节并拒绝控制字符；用户名不得包含冒号，释放时必须清零。 | 凭据边界和解码测试、代码评审 |
| SWR-PXY-003 | 代理解析错误不得包含原始 URL、解析器详情、用户名或密码，并必须拒绝路径、查询、片段和不支持的 scheme。 | 恶意 URL 脱敏测试 |
| SWR-PXY-004 | 自动/手动代理标签必须来自固定类型映射，不得包含主机、端口或凭据；核心代理层不得依赖 Tauri、Tokio 或网络 I/O。 | 精确标签测试、依赖评审 |
| SWR-TUN-001 | HTTP CONNECT 请求必须确定性构造 Host 和目标 authority，认证头仅在存在凭据时加入；含凭据请求缓冲在释放时必须清零且不得超过 16 KiB。 | 精确请求和边界测试、清理代码评审 |
| SWR-TUN-002 | HTTP CONNECT 响应必须在完整头和 16 KiB 上限内解析，仅接受 HTTP/1.0 或 1.1；只向外暴露固定错误及允许的状态码。 | 完整性、超限和状态矩阵测试 |
| SWR-TUN-003 | SOCKS5 必须显式协商无认证或用户名/密码认证，认证请求缓冲必须清零；域名目标必须交由代理解析以避免本地 DNS 泄漏。 | 字节级认证和远端 DNS 测试、旧隧道测试 |
| SWR-TUN-004 | SOCKS5 连接响应必须先验证版本、保留字、结果码和地址类型，再按 IPv4/IPv6/有界域名长度读取剩余字节。 | 响应形状和拒绝路径测试 |
| SWR-ROUTE-001 | 直连和手动代理必须在无平台调用时立即解析为封闭路由类型；路由标签不得包含端点或凭据。 | 模式分派和标签测试 |
| SWR-ROUTE-002 | 自动代理模式必须等待平台解析器返回唯一选定值；选定代理失败后不得隐式尝试后续 DIRECT 路径。 | 自动路由值测试、平台适配器代码评审 |
| SWR-ROUTE-003 | 平台解析器返回的不支持或损坏端点必须使用固定上下文拒绝，不得回显主机、端口、用户名或密码。 | 自动值恶意输入脱敏测试 |

## 需求约束

- 这里记录的是当前增量需求，不替代完整产品需求；后续迁移必须逐批补全协议、配置、保险库、诊断、音频和窗口需求。
- “必须”需求在对应版本验收前不得以 TODO、人工假设或仅编译通过关闭。
