# PC 端 Rust + Slint 与低延迟音频路线图

状态：**v2.1.0 实施中（核心契约提取与 Slint 原生壳层阶段；尚未达到版本验收门）**

制定日期：2026-11-14  
目标平台：Windows 10/11 x64、macOS 13+ Apple Silicon；Linux 继续作为开发与 CI 辅助平台。Android 保持独立 Kotlin + Compose 架构。

## 1. 总目标

桌面端将从 **Tauri 2 + WebView + HTML/CSS/JavaScript** 迁移到 **Rust + Slint**，随后分版本重构实时音频热路径。路线以可测量的性能结果为准，而不是以“完成代码替换”为准。

版本顺序固定如下：

| 版本 | 主题 | 核心结果 |
|---|---|---|
| **v2.1.0** | Rust + Slint 桌面迁移 | 桌面发行包不再依赖 Tauri、WebView UI 或 Node/Vite 运行路径，并保持现有功能对等 |
| **v2.2.0** | 无分配音频回调 | 预分配音频块池、无锁 SPSC 环形缓冲；回调只复制和推进指针，处理工作移出回调 |
| **v2.3.0** | 平台原生低延迟后端 | Windows WASAPI、macOS CoreAudio/ScreenCaptureKit；Linux PipeWire 作为辅助后端 |
| **v2.4.0** | 混音时钟 | 设备时间戳、漂移补偿、抖动吸收和过载时的新鲜度优先策略 |
| **v2.5.0** | 高灵敏度 VAD | 自适应噪声底、语音活动检测、可控 hangover，并评估降噪/AGC/AEC |
| **v2.6.0** | 内部帧大小 | 内部 10 ms 处理块，按协议聚合为 40 ms 网络帧 |
| **v3.0.0** | 生产化与本地模型 | 全平台生产化，并提供含 `canary-0.6b-turbo` 目标适配器的可选严格离线推理 |

> 版本号只在对应版本的验收门全部通过后推进。创建分支、加入依赖或让某个平台“能够编译”都不等于完成该版本。

## 2. 当前基线与先决工作

### 2.1 当前架构

```text
HTML/CSS/JavaScript 控制面板与字幕窗
                 │ Tauri IPC / events
                 ▼
Rust 会话、Gemini、代理、配置、诊断
                 │ bounded channels
                 ▼
CPAL / ScreenCaptureKit 音频采集与播放
```

现有优点必须保留：

- Gemini setup 完成前不发送 PCM；
- API Key 不进入 URL、普通设置或诊断日志；
- 有界音频、播放、字幕和诊断队列；
- 代理失败不静默回退直连；
- 翻译与纯转写语义严格分离；
- 40 ms 网络帧与最多 240 ms 排队预算；
- Windows/macOS 系统音频、译音播放、全局 F8、置顶字幕窗和加密保险库。

### 2.2 版本一致性

当前版本源存在历史不一致风险，例如 npm、Cargo、桌面配置和 Android 可能不是同一版本。开始 v2.1.0 前必须：

1. 以 `scripts/set-version.mjs` 为唯一版本更新入口；
2. 增加测试，检查 npm、Cargo、Slint 桌面包、Android 和发布产物版本完全一致；
3. 不在路线图提交中提前把源码标记为 v2.1.0；
4. v2.1.0 验收完成后再一次性同步并提交版本。

### 2.3 先建立性能基线

迁移前在相同硬件、设备、音频样本和网络条件下保存基线。至少记录：

- 应用冷启动时间与控制窗口首次可交互时间；
- 空闲/运行 RSS 和 CPU；
- 音频回调 p50、p95、p99、最大耗时；
- 每次回调堆分配次数和字节数；
- 采集到进入网络发送队列的 p50/p95/p99 延迟；
- 队列深度、丢帧数、过载恢复时间；
- 输入转写、首段翻译、首段译音耗时；
- 30 分钟混合采集的麦克风/系统音频时钟偏移；
- 断网、代理失败、设备拔出、休眠恢复和切换默认设备的结果。

基准数据不包含 API Key、音频内容或字幕正文。

## 3. 目标工作区架构

v2.1.0 先把 Tauri 绑定与业务核心分离，后续版本只替换音频层：

```text
Cargo workspace
├── crates/translator-core
│   ├── session / protocol / bounded events
│   ├── Gemini WebSocket + TLS
│   ├── proxy + diagnostics
│   └── settings + encrypted vault
├── crates/audio-engine
│   ├── capture/playback traits
│   ├── mixer/resampler/VAD
│   └── bounded realtime transport
├── crates/platform-audio
│   ├── windows-wasapi
│   ├── macos-coreaudio
│   └── linux-pipewire
└── desktop-slint
    ├── control window
    ├── transparent caption window
    ├── tray/global shortcut
    └── native packaging entry point
```

边界规则：

- `translator-core` 不依赖 Slint、Tauri 或具体音频 API；
- UI 只接收有界、脱敏的状态快照，不接收 PCM；
- 音频回调不能调用 UI、网络、日志、分配器或阻塞锁；
- Android 不链接这些桌面 crate，不因桌面迁移重新引入 Rust/JNI。

## 4. v2.1.0 — Rust + Slint 桌面迁移

### 4.0 当前实施进度

- 已建立 Rust 1.100 / edition 2024 Cargo workspace，并采用 Slint 1.18.1；版本来自 2026-11-14 后最新稳定发布检查；
- 已提取首个无 UI 的 `translator-core` 契约层，旧 Tauri 适配器与新 Slint 壳层共同使用模型、会话选项、代理模式、音源模式、状态和输入校验；
- 已建立可编译的 Slint 控制窗与独立字幕窗迁移壳层，但会话、设备、保险库、托盘、快捷键及平台窗口能力仍未接入，壳层会明确拒绝开始采集；
- 已增加跨 npm、Cargo workspace、旧 Tauri、原生 Android 和 Windows 包装的版本一致性门，并把历史基线统一为 `1.1.0`；这不是推进到 v2.1.0；
- 旧 Tauri 仍是生产入口，待 Slint 功能对等和真机门通过后才能删除。

### 4.1 实施顺序

1. 建立 Cargo workspace，并把协议、代理、诊断、配置与会话状态从 Tauri 命令中提取为普通 Rust API；
2. 用内存适配器为核心编写测试，确保不启动 UI 也能运行模拟 WebSocket 会话；
3. 建立 Slint 控制窗口，迁移模型、语言、音源、设备、代理、译音、Token saver 和诊断控制；
4. 建立 Slint 透明字幕窗口，支持置顶、拖动、缩放、锁定和鼠标穿透；
5. 实现桌面托盘/退出、F8 全局快捷键、窗口生命周期和单实例策略；
6. 迁移普通设置及加密保险库，保持现有文件格式可读；如需新格式，必须原子迁移并保留失败回滚；
7. 替换 Windows、macOS、Linux 的构建与发布任务；
8. 功能对等和安装升级测试通过后删除桌面 Tauri、Vite、jsdom UI 和 WebView 专用代码。

### 4.2 必须保持的功能

- 四种 Gemini 模型及其专属 setup；
- 翻译/转写模式的 UI 与播放器强约束；
- 麦克风、系统音频、混合输入及设备选择；
- 系统/手动/直连代理与安全失败策略；
- 原文/译文字幕、译音播放和中断清空；
- 加密保险库、设置迁移、诊断复制/清空；
- 字幕窗置顶、透明、缩放、锁定和穿透；
- F8、正常停止、关闭控制窗口后可达的退出路径。

### 4.3 v2.1.0 验收门

- 桌面发行包中不存在 Tauri/WebView UI 运行依赖；
- 不需要 Node.js 才能运行或打包桌面应用；
- 核心协议测试、代理测试、加密往返和错误脱敏测试全部保留；
- Windows/macOS 的控制窗口、字幕窗口、系统权限和安装升级完成真机验证；
- 空闲 RSS、冷启动时间和字幕渲染延迟相对基线无回退，并报告实际结果；
- 旧设置可读取，错误密码和损坏文件不会导致崩溃或数据泄露；
- Android CI 和行为不回退；
- 完成后才运行版本脚本推进到 `2.1.0`。

### 4.4 回滚策略

迁移期间保留旧 Tauri 入口用于 A/B 测试，但不得长期形成两套业务核心。Slint 只能调用提取后的共享核心。v2.1.0 发布前删除旧入口；若验收失败，回滚 UI 入口，不回滚已经测试通过的核心解耦。

## 5. v2.2.0 — 无分配音频回调

### 5.1 设计

- 启动音频流时按设备最大回调块预分配固定块池；
- 每个生产者使用独立 SPSC 环形缓冲，读写索引采用正确的 acquire/release 内存序；
- 回调只执行格式受控的复制/转换、写入时间戳、推进索引和计数；
- 块池耗尽时丢弃最旧或当前块，并增加原子计数，不分配、不阻塞、不写日志；
- 重采样、声道降混、混音、PCM16 编码和网络消息构造在独立工作线程完成；
- 停止时先断开生产者，再排空/清零包含语音的块，最后释放设备。

### 5.2 明确禁止

音频回调中不得出现：

- `Vec`/`String` 增长、`collect()`、Base64 或 JSON；
- `Mutex`、阻塞 channel send、文件/网络 I/O；
- UI 事件、诊断格式化或动态设备查询；
- 等待消费者追赶的自旋循环。

### 5.3 v2.2.0 验收门

- 分配器/基准证明稳定状态下音频回调 **0 次堆分配**；
- 回调 p99 小于单次设备缓冲周期的 25%，且无回调超过周期；
- 环形缓冲满/空、索引回绕、停止竞态和生产者过载有单元/并发测试；
- 30 分钟压力运行无无界增长、死锁或陈旧音频突发；
- 网络阻塞时延迟仍受预算约束，并优先保留新鲜语音；
- 完成后推进到 `2.2.0`。

## 6. v2.3.0 — 平台原生低延迟音频后端

### 6.1 Windows

- WASAPI event-driven shared mode；
- 优先使用 `IAudioClient3` 获取共享引擎周期；
- 麦克风捕获与 render endpoint loopback；
- 音频工作线程注册 MMCSS `Pro Audio`/`Audio`，退出时正确撤销；
- 处理默认设备变化、设备失效、独占占用和休眠恢复。

### 6.2 macOS

- 麦克风使用 CoreAudio AudioUnit；
- 系统音频继续使用 ScreenCaptureKit，但统一进入块池/SPSC 接口；
- 使用 host time 时间戳，处理路由/采样率变化和系统授权撤销。

### 6.3 Linux（辅助）

- 优先 PipeWire 原生流和时间戳；
- ALSA 只作为明确标注的兼容后备；
- 不因 Linux 辅助支持阻塞 Windows/macOS 发布，但 CI 必须可编译。

### 6.4 v2.3.0 验收门

- CPAL 不再位于 Windows/macOS 生产采集热路径；
- 平台后端都实现统一 trait、统一错误分类和确定性停止；
- 对比 v2.2.0，设备侧采集延迟或抖动有可复现改善，不能只报告“已使用原生 API”；
- 麦克风、系统音频、混合、设备热插拔和权限失败完成真机测试；
- 完成后推进到 `2.3.0`。

## 7. v2.4.0 — 混音时钟与漂移补偿

### 7.1 设计

- 每个音频块携带设备帧位置、单调时钟时间戳、采样率和 discontinuity 标记；
- 以单一输出时间线拉取麦克风和系统音频，而不是依赖线程固定睡眠；
- 用小幅异步重采样修正设备时钟漂移；
- 抖动缓冲只吸收短时波动，不突破总排队预算；
- 调度停顿后跳到最新合理时间点，不补发陈旧突发；
- 暴露脱敏指标：两路偏移、漂移 ppm、欠载、溢出和丢帧。

### 7.2 v2.4.0 验收门

- 30 分钟混合采集后两路偏移维持在目标窗口内（初始目标：绝对值不超过 20 ms）；
- 人工注入 ±100 ppm 时钟漂移后能够稳定收敛；
- 调度暂停、设备 discontinuity、采样率切换有确定性测试；
- 不扩大 240 ms 总排队上限；
- 完成后推进到 `2.4.0`。

## 8. v2.5.0 — 更灵敏的语音活动检测

### 8.1 设计

- 将固定 RMS 门升级为自适应噪声底 + 经过验证的 VAD；
- 候选实现优先评估 WebRTC VAD；RNNoise 作为可选降噪，不默认改变音色；
- 当前 40 ms 输入可在分析器内部拆成 VAD 支持的窗口，v2.6.0 再统一内部帧；
- 参数包含开始灵敏度、结束 hangover、最短语音和噪声底更新速度；
- 混合输入可在混合前分别检测，防止一路噪声永久打开门；
- AGC、降噪和 AEC 必须可独立开关并有失真/回声测试，不能把音量放大等同于灵敏度。

### 8.2 数据集与隐私

使用获得授权或公开许可的离线样本，覆盖：

- 轻声、远场、不同语言和不同说话人；
- 键盘、风扇、音乐、游戏和系统提示音；
- 麦克风回声与系统音频同时存在；
- 不把用户真实会话上传为测试集。

### 8.3 v2.5.0 验收门

- 报告语音漏检率、噪声误触发率和起止检测延迟；
- 相对固定 RMS 基线，在目标样本集上漏检和误触发均不回退；
- 轻声场景改善且不导致持续噪声大量消耗 Token；
- VAD 失败可安全回退为关闭门控，不中断会话；
- 完成后推进到 `2.5.0`。

## 9. v2.6.0 — 内部 10 ms 帧与协议聚合

### 9.1 设计

- 平台回调数据写入块池后，工作线程统一生成 10 ms、16 kHz、单声道内部块；
- 混音、VAD、漂移修正和中断处理都以 10 ms 为基本单位；
- 四个连续内部块聚合成一个 40 ms Gemini PCM16 网络帧；
- 停止/中断时不发送未定义长度的残帧；
- 网络拥塞仍以完整 40 ms 帧为单位丢弃旧数据。

### 9.2 v2.6.0 验收门

- 内部处理响应粒度为 10 ms，线上 Gemini 帧仍严格为 1,280 字节；
- VAD 开始检测延迟和混音抖动相对 v2.5.0 有可测改善；
- 分帧跨回调边界、残帧、停止和过载有属性/边界测试；
- CPU 不因更小帧产生不可接受回退，并报告各平台数据；
- 完成后推进到 `2.6.0`。

## 10. v3.0.0 — 生产化收尾

v3.0.0 重点是证明系统可以发布和维护，并在前期已完成的推理后端抽象上加入可选本地模型部署；不得在 v3.0.0 临时复制一套会话、音频或 UI 架构。

### 10.1 稳定性与恢复

- 网络切换、代理中断和可重试错误使用有上限的指数退避；
- 明确区分认证/配置错误与临时网络错误，禁止无意义重试；
- 设备拔出、默认设备变化、睡眠/唤醒和权限撤销可恢复或给出明确状态；
- 8 小时 soak test，无无界内存增长、线程泄漏和字幕/音频陈旧数据；
- 崩溃报告默认不包含密钥、代理凭据、音频或字幕。

### 10.2 安全与供应链

- 第三方依赖和许可证复核；
- 生成 SBOM、SHA-256 校验文件和可追踪构建信息；
- 模糊测试协议解析、配置迁移和代理握手；
- Windows 代码签名、macOS Developer ID 签名与公证；
- Android release keystore、签名和升级路径独立完成。

### 10.3 本地模型部署

- 核心提供与 UI/音频无关的 `InferenceBackend` 能力接口，云端 Gemini 和本地推理共用同一有界事件、字幕及取消语义；
- 首个目标适配器为用户指定的 `canary-0.6b-turbo`（实施时必须重新核对准确模型标识、许可证、发布方原始权重及支持的转写/翻译语言，不能仅凭名称下载第三方文件）；
- 本地模型作为可选组件按内容哈希和签名验证，模型目录不进入 Git，不自动执行模型仓库中的任意代码；
- 提供严格离线模式：启用后推理路径不得发起 DNS、HTTP、WebSocket 或遥测请求，不要求 Gemini API Key；
- 明确暴露能力差异。若本地模型不提供译音、双向翻译或某语言，不得用空输出伪装成功；
- 提供 CPU 与可用硬件加速后端的受测配置、内存/显存预算、量化格式、预热、取消和卸载策略；
- 在固定公开/授权测试集上记录识别/翻译质量、首段延迟、实时因子、峰值内存和持续运行温度；最低支持硬件上实时因子必须小于 1.0，具体硬件门槛随适配器证据固化；
- 模型推理属于非确定性外部组件。DO-178C 风格流程只覆盖本项目的集成、边界和验证证据，不把模型权重或输出宣称为已审定的安全关键功能。

### 10.4 发布验收

- Windows/macOS/Android 目标设备矩阵通过；
- 安装、覆盖升级、卸载和设置迁移通过；
- 性能相对初始 Tauri/CPAL 基线形成最终报告；
- 用户文档、隐私说明、故障收集指引与回滚方案完成；
- 只有上述门槛完成后才推进到 `3.0.0` 并创建正式发布。

## 11. 每个版本共同执行的质量门

每个阶段都必须：

1. 先写失败测试或可复现基准，再改实现；
2. 保持队列有界，明确满载策略；
3. 不在日志中记录密钥、代理凭据、PCM、字幕或服务端原始正文；
4. 运行 Rust 单元/集成测试、平台编译、Android 回归和发布构建；
5. 保存本版本与前一版本的性能对比；
6. 更新 README、技术栈、迁移状态和版本脚本测试；
7. 不以 CI 编译成功替代真实音频设备测试。

## 12. 执行依赖关系

```text
v2.1 核心/UI 解耦
  └─▶ v2.2 无分配回调与 SPSC
       └─▶ v2.3 平台原生后端
            └─▶ v2.4 统一时间戳与混音时钟
                 └─▶ v2.5 自适应 VAD
                      └─▶ v2.6 10 ms 内部帧
                           └─▶ v3.0 生产化验证与发布
```

不得并行合并会改变同一热路径的相邻阶段。可以并行准备测试设备、基准工具、签名流程和文档，但每个版本必须在上一版本验收后开始发布候选。
